## PR Review: #32

**Verdict**: REJECT

### Summary
This PR adds component value validation to detect invalid values (negative, zero, extreme). However, it has a critical bug: the validator fails to parse SI prefix notation (e.g., "1k", "10M") that the Circuit class uses, causing all valid component values to be rejected as errors.

### Acceptance Criteria
- [x] Check for negative resistance values — implemented correctly (value < 0.001 triggers ERROR)
- [x] Warn about extreme values (very large/small) — **PARTIALLY**: treats all out-of-range as ERROR, not WARNING
- [x] Detect zero-value components that might cause issues — implemented (0 < min triggers ERROR)
- [x] Check for realistic ranges based on component type — implemented per R/L/C
- [x] Provide suggestions for typical values — implemented in error messages

### Detailed Analysis

**The Critical Bug:**

The Circuit class stores component values as strings:
```python
# From circuit.py
circuit.add_resistor("R1", 1, 0, "1k")  # stores {"resistance": "1k", ...}
circuit.add_capacitor("C1", 1, 0, "10u")  # stores {"capacitance": "10u", ...}
```

But the validator does:
```python
# component_values.py line ~117
try:
    value = float(resistance)  # FAILS on "1k" - raises ValueError
except (ValueError, TypeError):
    return self._create_issue(
        issue_type="invalid_resistance",
        severity=Severity.ERROR,
        message=f"Resistor '{name}' has invalid resistance value: {resistance}",
        ...
    )
```

The codebase already has a `parse_value()` function in `parser.py` that handles SI prefixes:
```python
>>> from circuit_sim.parser import parse_value
>>> parse_value("1k")
1000.0
>>> parse_value("10M")
10000000.0
>>> parse_value("1u")
1e-06
```

The validator must use this function to correctly parse values before validation.

### Recommendation

Fix the HIGH severity issues before merging:
1. Import `parse_value` from `..parser` and use it in `_validate_resistance`, `_validate_capacitance`, `_validate_inductance`
2. Add tests for the new validator
3. Remove unused `Any` import
4. Optionally: consider WARNING vs ERROR distinction for extreme but valid values
